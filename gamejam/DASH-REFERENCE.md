# 第七版：雙軌對照

獨立入口 `dash.html`。前六版保留；本版沒有選曲或三種難度，只使用影片中的《草蛇驚一》Lv.9 重建譜面。D / F / ↑ 打上軌並跳起，J / K / SPACE / ↓ 打下軌。可以兩手交替敲同軌，長按一軌時敲另一軌；觸控使用下方兩個按鈕。

## 來源與精度

- 使用者提供的影片：[【MUSE DASH】草蛇惊一 大触 Lv.9 FC](https://www.bilibili.com/video/BV1yvaz6eEKS/)，上傳者「一具音游人」。本版是非官方玩法對照原型，沒有使用原遊戲程式、角色或背景圖。
- 音訊為該影片的音軌轉存，保留開頭時間軸與原遊戲打擊音效，**不是乾淨的歌曲母帶**。因此玩家沒有按鍵時也可能聽到原錄影的擊中聲；本版不再疊加假打擊音來掩蓋這個差異。
- 畫面為 960 × 720、30 fps。影片沒有可用的逐鍵輸入紀錄。以連擊數字的第一次可辨識影格定位成功判定，檢視事件前後影格確認上下軌、长按與連打。不是用音量波峰隨機生成譜面。
- `assets/dash/video-timing.json` 保留全部 514 個 Combo 的來源影格。1–4 Combo 因畫面沒有顯示連擊數，改採開頭擊中影格；7 個同時判定的中間數字沒有出現在影片中，採成對判定的共同影格。
- 換算時扣除一個顯示影格（33.33 ms）作為初始顯示延遲估計。這不是原遊戲譜面匯出：影片本身有 PERFECT / GREAT、EARLY / LATE，以及數字動畫延遲，**誤差可能超過單一影格，不能宣稱毫秒級精準或完全相同**。偏移滑桿可處理一致的整體誤差，無法修正各個音符不同的偏差。
- 15 段長按（30 個端點判定）、2 段連打、482 個普通判定，總计 514。冰刺與音符補給物另外依畫面估計通過時間，不計入 Combo。個別物件種類與避障時間仍可能存在轉錄誤差。

## 可比較的玩法

1. 兩條固定軌道，音符由右往左抵達固定判定環。角色的捲動畫面與短促攻擊代替第六版的呼吸關卡流程。
2. 冰藍魚對上軌、金色魚對下軌；發光水流按住直到尾端，另一軌仍可打擊。
3. 大金魚區段左右交替連打。兩段各要求 12 / 16 次有效按下；原片的 33 / 44 HITS 是玩家實際連打次數，不能由此推論原遊戲成功門檻。
4. 冰刺需要上軌按鍵跳過。跳躍期間打下軌不取消跳躍，適合避障與打擊交替。
5. 體力、連擊、準確率、快慢回饋和失敗結果。練習不中斷、自動演示、段落練習均明確標示，不冒充正常通關。
6. 所有判定以同一個音訊時鐘驅動，使用輸出裝置時間戳補償，沒有用動畫幀數累積音樂時間。暫停與切換背景會停止音訊；恢復時重新取得音訊時鐘。

## 和原遊戲仍不同的部分

這是影片重建的比較版本，不是 MUSE DASH 引擎的完整複製。原作的精確判定窗、角色技能、敵人傷害、Fever、長按加分與排行榜公式無法由這一段影片完整確定。本版固定採 PERFECT ±50 ms、GREAT ±110 ms，錯過一般音符扣 20 體力、撞冰刺扣 30；連打門檻和跳躍窗口是原型規則。這些差異應與譜面同步問題分開評估。

美術完全沿用第六版 `assets/tide/` 冰藍手繪素材，加上雙軌、命中光環、水花碎光、長按水流與連續彈簧動作。第六版的氧氣、進食成長和結局沒有搬進來，避免改變雙軌比較的玩法規則。

## 重建與驗證

- `python tools/build_video_chart.py` 從來源影格紀錄、人工核對軌道與端點，重建 `assets/dash/chart.json`。
- `node --test dash.test.cjs` 驗證 514 判定、長按配對、不同幀率自動演示、雙軌輸入、提前放開、連打、避障與練習模式。
- 遊玩結果列出的快慢平均與分散程度僅統計命中的按鍵。自動演示只證明程式能依這份重建譜面執行，不能當成原作譜面完全一致的證據。
